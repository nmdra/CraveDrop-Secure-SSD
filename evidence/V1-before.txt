# V1: Missing authentication on payment actions

Baseline reference: baseline-vulnerable (`cb68a377f5b8cdc3b12f86883ac6fb703ef5e405`)
Primary mapping: CWE-306: Missing Authentication for Critical Function

## Reproduction request

```bash
curl -i -X POST http://localhost:5002/api/payments/create-payment-intent \
  -H 'Content-Type: application/json' \
  --data '{"amount":1,"currency":"usd"}'
```

## Baseline source result

- PASS: payment-service/src/index.js:23 contains `app.use('/api/payments', paymentRoutes);`
- PASS: payment-service/src/routes/payment.route.js:6 contains `router.post('/create-payment-intent', createPaymentIntent);`
- PASS: payment-service/src/routes/payment.route.js:7 contains `router.post('/confirm-payment', confirmPayment);`

Impact: The payment actions are mounted without an authentication middleware, so an anonymous caller reaches payment functionality.

This Phase 3 artifact is a reproducible source-level baseline proof.

## Live baseline response

Run against the isolated baseline checkout with a synthetic Stripe test key and no `Authorization` header:

```text
HTTP/1.1 500 Internal Server Error
Content-Type: application/json; charset=utf-8
{"error":"Invalid API Key provided: sk_test_**************_key"}
```

The handler was reached without authentication. The synthetic Stripe key intentionally prevents a real payment request. The response contains no real credential.
